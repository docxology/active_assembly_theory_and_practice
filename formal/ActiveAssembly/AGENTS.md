# ActiveAssembly (Lean library) — Agent Guide

## Overview

This directory is the `ActiveAssembly` Lean 4 library declared by
[`../lakefile.toml`](../lakefile.toml). It carries the project's entire
kernel-checked surface: a bounded accumulator semantics, a normalized machine
state, a closed-world instruction IR, and a generated correspondence fixture.
Everything here is deliberately small and closed-world. The trusted base is the
Lean kernel plus the imported core/standard library — no external solver output
is accepted as a certificate.

## `Semantics.lean`

The operational core. `MOD64 = 2 ^ 64`, `Word64 = Fin MOD64`, and the
constructors `word64`, `add64`, `sub64`, `inc64`.

`Op` has five constructors: `mov (value : Word64)`, `add (value : Word64)`,
`sub (value : Word64)`, `inc`, and `nop`. `step` interprets one `Op`; `run`
folds a `List Op` over an initial word. `ObservationallyEqual left right` is
universal over every `Word64` initial state.

Theorems: `mod64_pos`, `inc_inc_eq_add_two`, `nop_is_identity`,
`constant_add_equivalence`, `neutral_nop_equivalence`,
`changed_subtraction_is_not_equivalent` (an explicit near miss), and
`run_nop_append`.

## `NormalizedMachine.lean`

The Lean-side schema for the bounded machine state used by the promotion
tranche. `MOD64N`, `Word64N = Fin MOD64N`, `word64n`, plus:

- `MachineStatusN` — `running`, `halted`, `unsupported`, `boundExceeded`,
  `exceptional`.
- `FlagsN` — `cf`, `pf`, `af`, `zf`, `sf`, `of`, and a `defined` predicate.
- `MachineStateN` — `gprs : Fin 16 → Word64N`, `rip`, `flags`,
  `memory : Nat → UInt8`, `stackLower`/`stackUpper`,
  `memoryLower`/`memoryUpper`, `stepIndex`, and `status`.

Operations: `write32N` (zero-extending), `inc64N`, `incStateN`, `adc64N`, and
the predicate `memoryInBoundsN`.

Theorems: `mod64n_pos`, `write32_zero_extends`, `inc_preserves_cf`,
`adc_zero_carry`, and `unsupported_is_explicit`.

The Python reference interpreter and the Unicorn receipt use the corresponding
fields and the same width/flag boundary; this file is a schema, not a claim
that x86-64 has been formalized.

## `IR.lean`

A closed-world classification vocabulary shared conceptually with the Python
receipt layer:

- `OperandWidthN` — `w8`, `w16`, `w32`, `w64`.
- `FlagN` — `cf`, `pf`, `af`, `zf`, `sf`, `of`.
- `OpcodeN` — 29 constructors: 28 named opcodes from `mov` through `ret`, plus
  an explicit `unsupported`.
- `ControlFlowN` — `fallthrough`, `branch`, `call`, `return`, `unsupported`.
- `MemoryAddressN` — `base`, `index`, `scale`, `displacement`.
- `IRInstructionN` — opcode, width, immediate, memory address, flag reads and
  writes, control flow.

`OpcodeN.isDeclaredSupported` returns `false` exactly for `unsupported`, with
`explicit_unsupported_is_not_supported`, `declared_opcode_decidable`, and
`declared_opcode_has_decidable_status` making that boundary decidable rather
than conventional.

## `GeneratedCorrespondence.lean`

Generated by [`../../src/lean_bridge.py`](../../src/lean_bridge.py) and marked
`do not hand edit`. It serializes a Python-selected `Word64` boundary fragment
into Lean and compiles it with kernel-checked equalities:
`generatedBridgeInitial`, `generatedBridgeProgram`, `generatedBridgeExpected`,
and `generated_trace_matches`; then `generatedGpr`, `generatedMachineInitial`,
`generatedMachineAfterInc`, and the theorems
`generated_machine_state_rax_increment`,
`generated_machine_state_other_registers_preserved`,
`generated_machine_state_preserves_cf`,
`generated_machine_state_increments_step`, and
`generated_machine_state_preserves_bounds`.

The bridge is evidence for that generated fixture only. It does not turn the
Python lifter, the Capstone decoder, the Unicorn comparison, or the full
declared instruction subset into a mechanized x86 theorem.

## Best Practices

- Do state the claim boundary in a docstring comment beside every new theorem.
- Do keep `unsupported` reachable and explicit in both `OpcodeN` and
  `ControlFlowN`; erasing it would silently widen the modelled domain.
- Do regenerate `GeneratedCorrespondence.lean` rather than editing it.
- Do not import an external Lean package without updating
  [`../lake-manifest.json`](../lake-manifest.json) and the stated trusted base.
